# 日志专项开发

先读[日志机制](../../../docs/domains/logging.md)；字段变化再读[事件参考](../../../docs/domains/log-events.md)。Rust 实现沿用[主流程](../rust-readable-apps/SKILL.md)，任务取消问题进入异步专项。

## 先定义观察对象

明确事件发生在接纳、发送、响应、校验还是事务提交；名称和级别描述真实结果。稳定 event 与 schema_version 用于消费者分类，message 供人阅读。字段采用原生数值、布尔和明确单位；枚举标签、缺失值与零值分开解释。

累计、区间、当前占用和抽样分别定义。不能从日志条数推导事务数，不能把不同阶段或跨区间分子分母直接算成功率。耗时说明起止、取消是否记样本、分位是精确值还是桶界。高基数字段与底层错误说明必须有实际诊断用途和容量约束。

## 保持输出与任务边界

检查过滤发生的时机、各 sink 的队列策略、丢弃可见性和 writer guard 所有者。日志失败不应无意改变产品控制流；若需要可靠证据，先设计独立持久化语义。同步 span guard 不跨 await 持有，异步上下文使用 Instrument 等匹配库机制，具体用法按需读 [tracing 参考](references/tracing.md)。

## 联动与验收

修改前查所有生产者、事件测试和 Python 消费者；同步事件名、版本、类型、单位和缺失语义。输出机制变化核对两端、过滤、轮转、run_id 和关闭；字段变化核对聚合与诊断结果，不顺带新增日志配置框架。

按项目[验证指南](../../../docs/development/validation.md)选择 rust、tools 或 docs 的受影响并集。审查给位置、触发条件、影响和证据，区分必须修复、建议及待验证推断；测试通过不能表述为运行日志绝不丢失。
