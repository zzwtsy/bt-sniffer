# 设计规则与建议起点

本文件描述一套可复用的设计方法，来源是用户提供的 Pendant 页面截图与本次分析。
它不是该站的 CSS 提取结果。背景色经图像像素核对；其余参数是为新项目给出的可调整建议。
参考图中的文字、品牌及界面截图不是供新产品直接使用的生产素材。

## 1. 决策优先级

先保持任务和功能完整，再保证阅读与操作可用，然后解决结构与层级，最后处理装饰。
用户已指定的品牌、现有设计系统、技术约束和设备要求优先；不强行将所有项目改为米白与陶土色。
默认方向：宽松的页面框架、紧凑的内容组织、低装饰噪声、少量语义色、稳定的组件规则。
不把“安静”当成信息量小，也不把“精致”当成字号小。

## 2. 把感受转成决策

| 感受 | 可执行的决策 | 应检查的结果 |
|---|---|---|
| 有呼吸感 | 页面区块间距大于组内间距；共享版心 | 关联项成组，区块间有清楚停顿 |
| 安静 | 限制大面积强调色，淡化非交互分隔线 | 主内容先于装饰进入注意 |
| 精致 | 相同角色共享字号、行高、边框、图标和圆角 | 不出现同类控件不同规格 |
| 密而不乱 | 一套列表行结构，标题形成固定扫描列 | 列表增长后仍能快速浏览 |
| 有层次 | 仅少量主角或浮层使用明显投影 | 主要展示物与普通内容有明确区别 |
| 整体完整 | 页面间共用主题语义和组件 | 首页、列表、文档没有风格断层 |

## 3. 布局

初始参考值（rem 按项目根字号解释，不修改用户或项目根字号）：

| 项目 | 建议起点 | 调整依据 |
|---|---|---|
| 外层版心上限 | 60rem | 工具界面多列任务可放宽，不强行压窄 |
| 阅读列上限 | 42rem | 真实语言、字号、段落结构 |
| 首页介绍列上限 | 32rem | 产品定位和文案长度 |
| 产品展示上限 | 56rem | 图像比例与可辨认程度 |
| 页面水平边距 | 1–2rem | 窄屏至少保留合理操作边缘 |
| 主要区块间距 | 3–6rem | 内容量、视口高度和页面任务 |
| 组内间距 | 0.5–1rem | 让相关元素形成一组 |

不要从整页截图反推浏览器真实 CSS 像素；像素比例、页面缩放和长图压缩可能不同。
不要固定整体高度以复制截图空白。短页采用自然的伸展布局，页脚不得遮住内容。

简单外框示例，仅在项目没有既有布局组件时采用：

```css
.calm-page {
  box-sizing: border-box;
  inline-size: 100%;
  max-inline-size: calc(var(--calm-width-page) + 2 * var(--calm-gutter));
  margin-inline: auto;
  padding-inline: var(--calm-gutter);
}
.calm-reading {
  inline-size: 100%;
  max-inline-size: var(--calm-width-reading);
}
```

首页、列表和文档可以使用不同内部宽度，但仍要说明它们与外框的对齐关系。

## 4. 配色与对比

`assets/tokens.css` 是局部作用域的起始色板，不包含全局 reset，也不自动切换主题。
将变量映射到现有设计系统；不存在设计系统时，再把类和主题属性放到适当的根容器。
主题选择逻辑应尊重用户设置及系统偏好；不要只导入变量文件就声称实现了主题功能。

色彩角色要分开：背景、面板、正文、辅助正文、普通分隔线、控件边界、强调色、强调色上的文字、焦点。
暖浅底的样本值为 #F7F4EE，暖暗底的样本值为 #1B1B1A；不是所有项目都必须使用这两个值。
默认浅色强调为灰蓝，深色强调为陶土色；品牌需要稳定主色时，保留品牌并分别调整明度和对比。

低对比仅用于不承担必要识别功能的装饰。例如：正文列表的辅助横线可以较淡；
识别输入框、选中状态、错误状态或键盘焦点所必需的信息则不能任意淡化。
`--calm-border-subtle` 不应用作唯一的输入框边界；这类用途使用 `--calm-border-control` 并检查实际组合。
颜色名称不是通过测试的证明，实际前景、背景、透明度和状态共同决定结果。

参考 WCAG 2.2：普通文本通常至少 4.5:1；符合大字定义的文本至少 3:1。
为避免误判大字资格，本 skill 的默认文字颜色对按 4.5:1 检查。
识别必要的非文本控件与状态信息按适用条款检查 3:1；装饰线不一律适用这个阈值。

## 5. 文字

保留项目字体；无约束时使用系统无衬线字体及中文回退，避免为参考风格新增远程字体依赖。
正文建议从 1rem 开始，工具列表可从 0.875rem 开始，元信息从 0.8125rem 开始；
这些是起点而非 WCAG 字号标准，不用于降低重要信息的可读性。
正文行高可从 1.6 开始，密集列表从 1.45 开始，标题从 1.2–1.3 开始。
先调行长和换行，再调字号。大标题不应靠截断、溢出或隐藏文案维持造型。

同一页面通常只需少量文字角色：主标题、区域标题、正文、辅助信息。
数字列需要稳定对齐时，可使用现有字体的等宽数字特性；不要擅自替换正文为等宽字体。
中文标题不要照搬英文的大幅负字距；检查中英混排、标点、按钮基线和字重回退。

## 6. 页面配方

### 产品首页

顺序优先为定位、简短解释、主要入口、真实产品展示、能力说明、常见问题。
只放任务所需的内容；不默认添加虚构用户量、客户 logo、评论或获奖信息。
介绍文字比产品展示窄。产品窗口可以有可见投影；普通说明面板保持平面。
不要把网站截图当作新产品自己的界面；没有真实产品图时，明确使用演示或占位内容。

### 问题与讨论列表

使用一个列表容器和轻分隔线。稳定安排标题与元信息，不给每行单独投影。
筛选条件聚合在列表上方，新增操作与筛选区有清楚关系。
分类可以使用小标签；状态圆点必须有非颜色的可理解表达，且关键说明不能仅依赖鼠标悬停。
长标题允许换行，行高随内容伸展；不要使用固定高度裁掉内容。
移动端保留关键操作、标题和状态；元信息可以放到下一行，而非全部隐去。
搜索、筛选和空结果必须有真实行为或明确的演示范围，不能只有外观。

### 更新日志与文档

使用较窄阅读列，不要求强行填满外框。
版本、日期、下载入口形成稳定结构；长段落适当换行。
展开/折叠优先使用现成的可访问组件或原生 details/summary。
不把交互按钮嵌套在另一个交互按钮里；展开控件与下载链接的结构应分别可操作。

## 7. 形状、状态与动效

普通面板圆角可从 8–12px 开始；紧凑筛选器、分类标签与按钮可用胶囊形。
这是层级区分，不是要求所有控件必须同一种圆角。
图标统一来源与线重，优先使用已安装图标集。图标按钮必须有可访问名称。
明显阴影留给产品展示、菜单或对话框等有理由的元素；不要为了统一给每个面板都加投影。

默认桌面操作区可从 36px 高开始；触控主要目标采用 44px 级或更宽松的操作区。
这些是本方案的推荐值，不是把 WCAG 最低值改写为 44px。
WCAG 2.2 的目标尺寸最低条款通常是 24×24 CSS px 或满足列出的例外；应核对实际几何、间距和情境。
视觉控件小，不代表点击区也必须小；不要让扩大的点击区覆盖相邻操作。

只给有功能目的的状态切换添加短动效；尊重 prefers-reduced-motion。
错误、加载、空状态和禁用态必须延续同一套视觉规则，不在异常时临时引入另一套高对比风格。

## 8. 常见偏差与修正

- 整页显得空：先把关联信息收紧，再检查缺失内容，不先放大所有字和按钮。
- 列表显得乱：统一字段位置、标签规格与扫描列，不先删掉必要数据。
- 界面显得淡：提高正文和操作对比，不把全部边框一起加深。
- 界面显得重：优先去掉重复投影、粗边框和大块强调色，不缩小文字。
- 桌面好看、手机难用：重新排列内容与操作，不把桌面按比例缩小。
- 深色主题面板无文字：检查主题变量、继承、透明度和渲染状态；不可把未显示内容解释为高级留白。
