# 交付验收

只记录实际检查过的项目。区分“通过”“失败”“不适用”和“未验证”。
代码检查、色板计算、浏览器截图和人工审阅不是互相替代的证据。

## 1. 任务与功能

- 原有文案、数据字段、关键操作与路由没有因美化而丢失。
- 搜索、筛选、链接、展开折叠和主题切换在任务范围内可用。
- 新增演示内容明确标识；不把示例反馈、状态或截图伪装为真实服务数据。
- 检查任务适用的 loading、empty、error、disabled 状态。
- 使用项目实际存在的构建、类型和测试命令，记录命令与退出结果。

## 2. 视觉

- 导航、页面标题、列表与页脚有明确且稳定的对齐关系。
- 主要区块间距明显区别于组内间距；不是平均撒开所有元素。
- 第一视觉重点来自主要内容或操作，不是阴影、纹理或装饰图标。
- 相同类型的按钮、图标、标签、圆角与字号规格一致。
- 密集记录形成稳定扫描列，不出现整页独立卡片的装饰堆叠。
- 稀疏页面自然留空，不出现为了撑高而造出的空面板或固定高度。
- 至少一个普通内容页与首页共享同一套规则；只改一个页面时检查共享组件不影响其他页。

## 3. 浏览器与响应式

默认检查宽度 1440、768、390 CSS px；额外检查 320 CSS px 的回流与溢出。
这些是测试视口建议，不是必须采用的 CSS 断点。
用户指定设备时以其为准；有浅深主题就分别检查相关状态。

- 保存并实际查看渲染截图；不要仅确认截图文件存在。
- 检查长标题、长 URL、中英混排、空列表、少量记录与大量记录。
- 没有页面级横向溢出；确需二维查看的数据区域有明确局部滚动与可用操作。
- 移动端导航和筛选不重叠，主要按钮不被挤出屏幕。
- 小屏不是把桌面整体缩小；关键内容和操作没有无提示消失。
- 200% 文本缩放后仍可阅读和操作；对 320 CSS px 等价宽度另做回流检查。
- 暗色主题没有消失的正文、纯白残留面板、错色原生控件或不可见焦点。
- 页脚和固定元素不遮挡内容，布局没有依赖 screenshot 的整体高度。

## 4. 可访问性

- 普通文本与实际背景达到适用的 4.5:1；符合大字定义时才采用 3:1。
- 识别控件和状态所必需的非文本信息满足适用的 3:1 要求。
- 不把极淡装饰分隔线误用于唯一控件边界。
- 键盘可到达所有操作；焦点可见且不被遮挡，没有不必要的键盘陷阱。
- 使用正确语义与标签；导航、筛选、tabs 和按钮不因外观相似就混用角色。
- 状态有非颜色表达；不能仅依赖彩色小点或只有鼠标能看到的 tooltip。
- 点击目标符合适用尺寸或间距要求；触控主要操作采用更宽松的尺寸。
- 尊重减少动效偏好；不存在无功能的持续闪动或自动动画。

## 5. 色板脚本的范围

在 skill 根目录运行：

```bash
python scripts/check_contrast.py --self-test
python scripts/check_contrast.py --css assets/tokens.css
python scripts/check_contrast.py --foreground '#68645D' --background '#F7F4EE' --minimum 4.5
```

脚本仅支持不透明 #RGB 或 #RRGGBB；CSS 模式只认识附带文件的两种简单主题块。
它不解析任意 CSS、不解析透明度合成、不读取浏览器 computed style、不检测字号和点击区。
移植至 Tailwind 或项目 tokens 后，用实际最终颜色重新计算，或使用项目现有浏览器检测工具。
即使脚本全部通过，也不能写“整个网站符合 WCAG”。

## 6. 建议交付记录

```text
范围：实现或评审的页面与组件
主要改动：布局、层级、密度、配色和交互中的关键变化
功能验证：实际执行的步骤和结果
视觉验证：视口、主题、内容状态、截图是否已查看
其他检查：实际命令、对比度或键盘检查
未验证项：缺少浏览器、数据、凭据或环境导致的限制
```
