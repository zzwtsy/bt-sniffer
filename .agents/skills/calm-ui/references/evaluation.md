# Skill 评估用例

此文件是待执行的评估计划，不代表这些 Agent 任务已经运行通过。
分别评估：是否正确触发、是否完成任务、是否改善目标风格、是否引入回归。

## 对照方法

选择同一代码基线、同一任务、同一模型与工具权限，分别在不启用和启用 skill 的独立会话中运行。
不要让第二次运行继承第一次实现或额外提示。复杂任务可重复运行，记录波动。
比较浏览器截图、功能结果和工具记录，不以 Agent 自称“高级感”作为评分依据。

## 硬性失败

关键功能失效、必要内容丢失、关键文字无法阅读、键盘无法操作、移动端主要操作不可达、
违背指定品牌或任务范围、虚构验证记录，任一项出现都不能只凭截图好看判定成功。

## 风格评分

分别对信息层级、对齐与留白、列表扫描性、颜色角色、组件一致性评分 0–2：
0 = 明显缺失或相互冲突；1 = 部分成立但有重复偏差；2 = 清楚且稳定。
建议先满足所有硬性门槛，再争取至少 8/10 的风格评分；该分数是本包的自定义标准，不是行业认证。
对照未启用版本检查是否有实际提升；没有提升就删改对应规则，而不是不断延长 skill。

## 修订记录建议

每次只调整一个主要问题：误触发改 description；信息结构差改工作流程；
同类组件不一致改 token/组件规则；字号过小或功能损坏补强边界与验收。
至少回归执行原失败用例、一个不同类型正例、一个不应触发的反例。
