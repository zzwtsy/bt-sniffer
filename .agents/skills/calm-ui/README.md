# Calm UI — 安静、精致的界面设计 Skill

本包把本次 Pendant 截图分析转成可执行的工作流程：阅读项目 → 组织信息 → 建立语义 tokens →
实现组件 → 浏览器验证与修正。适合产品首页、问题列表、讨论区、更新日志，以及同类风格的界面改造。
不以米白、小字和圆角本身为目标，也不是 Pendant 的官方 skill 或源码复刻。

## 文件分工

- `SKILL.md`：给 Agent 读取的入口，包含触发条件、范围、流程、关键规则和交付要求。
- `references/design-system.md`：布局、文字、配色与页面配方，按需要读取。
- `references/qa-checklist.md`：功能、视觉、响应式和可访问性检查。
- `references/evaluation.md`：作者用于评估触发与输出的正例、反例和对照方法。
- `references/sources.md`：规范来源、版本核对日期与截图来源说明。
- `assets/tokens.css`：浅色/深色语义 tokens 的建议起点，不是完整 UI 组件或主题切换实现。
- `assets/reference-*.png`：本次提供的六张参考截图，只按当前页面类型查看。
- `scripts/check_contrast.py`：可选的纯 Python 颜色对比计算；不联网、不修改文件。
- `VALIDATION.md`：本次实际执行的包检查及其限制。

## 最小结构是什么

一个符合开放格式的 skill 至少是一个目录，其中有 `SKILL.md`。
该文件先写 YAML frontmatter（包含 `name`、`description`），再写 Markdown 指令。
目录名与 `name` 一致。`description` 要同时表达做什么、何时使用，以及必要的适用边界。
其他文件夹是可选的；简单 skill 不需要脚本。

本包使用通用字段，没有加入某一家宿主独有的工具权限、参数插值或子 Agent 配置。
兼容性仍取决于宿主实现及其本地文件、图片和工具能力；格式兼容不代表所有平台操作完全一致。

按所使用的 Agent 选择一个位置，解压后将整个 `calm-ui` 文件夹放入该位置。
不要只复制入口文件，否则相对引用的规则和素材会缺失。
本次仅生成文件，并未替你安装到本地环境。

## 一个有效任务应该提供什么

```text
使用 calm-ui 改造项目的 /issues 页面。
目标：安静、紧凑但可读，不做宣传型大卡片。
保留：现有组件库、品牌蓝、搜索和筛选逻辑、全部数据字段。
范围：只修改此页面及必要的共享样式，不改变后端接口。
验证：检查长标题、空结果、深色主题、键盘导航和手机布局。
请先读项目，再实施；交付时列出实际验证结果和未验证项。
```

Skill 固化方法；当前任务提供页面、内容、数据、保留项和验收范围。
不要把一次任务的用户名、API 地址、业务数据或一张截图的固定宽度写成通用规则。

## 如何写出自己的 Skill

先明确一类重复任务，再写触发范围。把偏好写成“条件 → 动作 → 检查”，而不是形容词堆叠。
主文件只保留每次都要执行的内容；把色板、详细组件规则、截图和长检查表放到附属文件。
必须说明何时读取每个附属文件，不能只写“参考附件”。

第一次写完后，找一个真实任务运行，并与未使用 skill 的版本比较。
分别检查是否误触发、有没有保留原功能，以及目标风格是否真正改善。
对重复失败做定向修订；不要因一次失败就把主文件扩成通用前端百科。
评估计划见 `references/evaluation.md`。目前这套 Agent 任务评估仍待在实际项目中执行。

## 可选脚本

仅检查指令与视觉参考不需要 Python。执行对比度脚本需要 Python 3.9+，无第三方依赖。
从 `calm-ui` 根目录运行：

```bash
python scripts/check_contrast.py --self-test
python scripts/check_contrast.py --css assets/tokens.css
python scripts/check_contrast.py --foreground '#68645D' --background '#F7F4EE' --minimum 4.5
```

返回码：0 为所选计算检查通过；1 为某颜色对不达设定阈值；2 为输入或文件格式错误。
CSS 模式仅适用于附带文件的两个平面主题块，不是任意 CSS 解析器。
脚本通过不能证明整个页面满足可访问性标准；仍需检查真实 DOM、状态、交互与浏览器渲染。
