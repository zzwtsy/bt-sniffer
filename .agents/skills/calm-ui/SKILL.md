# Calm UI

把界面做得安静而不含糊，精致而不脆弱：**外部宽松，内部高效；内容清楚，装饰退后。**
这是从参考截图提炼的设计方法，不是 Pendant 的源码、品牌规范或像素级复刻模板。

## 适用边界

- 遵守宿主、仓库和用户指令。保留既有品牌、技术栈、组件、内容与业务行为；默认仅修改任务涉及的范围。
- 用户只要求分析或评审时，不改文件。用户要求实现时，交付可运行的界面，而不是停留在风格建议。
- 数值是起点，不是硬性设计标准。用户需求、可访问性和真实内容优先于“像参考图”。
- 不把截图中的缩放、小字号、极淡文字、第三方浮层或疑似未加载内容复制成设计特征。
- 不新增依赖、外部字体、跟踪脚本或部署操作，除非任务确有需要且符合环境授权；不得虚构验证结果。

## 工作流程

### 1. 先读项目，确定任务

检查目标页面、现有样式与组件、依赖清单、运行及测试命令、主题机制和目标设备。
明确是新建、改造还是评审；识别需要保留的内容、字段、操作和状态。
如果缺少会改变实现方向的必要信息，提出一个聚焦的问题；其余采用合理默认值并记录。
没有代码访问能力时，只做可执行的方案；没有浏览器时，不声称看过运行结果。

### 2. 定义信息结构，再选择装饰

在实现前明确：页面主任务、最重要的内容、主要操作、内容类型和阅读宽度。
用几句话记录版心、主要对齐线、局部密度、浅深主题策略，不必让用户逐项确认。
先组织内容和留白，再设置颜色、圆角与阴影。

### 3. 选择相关参考，建立语义 tokens

首次建立或改造视觉系统时，阅读 [设计规则](references/design-system.md)。
没有既有 tokens 时，以 [CSS 起点](assets/tokens.css) 为基础；已有 tokens 时映射语义，不整套覆盖。
只在需要视觉比对时查看相关截图，不一次加载全部图片：

- 首页：[浅色首页](assets/reference-home-light.png)。
- 密集列表：[浅色问题页](assets/reference-issues-light.png)；深色主题再看 [深色问题页](assets/reference-issues-dark.png)。
- 稀疏内容：[讨论页](assets/reference-discussions-light.png)。
- 文档与折叠列表：[浅色版本页](assets/reference-releases-light.png)；需要时看 [深色版本页](assets/reference-releases-dark.png)。

复用布局比例、层级和密度关系，不复制商标、文案、真实用户帖子或无关浮层。

### 4. 应用六条核心规则

**版心与留白。** 导航、标题、正文和页脚共享外层框架。使用响应式边距和 max-width，
不要把“桌面截图占屏幕约一半”写成 `width: 46%`。主要区块间留足空白，关联内容内部保持紧凑。
阅读型内容可以比外框窄；工具型多列内容确有需要时可以更宽。

**对比与色彩。** 弱化装饰线和非交互容器，不弱化正文、操作与焦点。
新建且没有品牌要求时，使用暖中性色底和少量低饱和强调色。
区分普通分隔线与识别输入框、状态、焦点所必需的边界。深色主题单独配色，不机械反相。

**文字。** 先用位置、间距、字重和颜色建立层级，再增加字号差异。
正文保持可读，不通过全局缩小字号获得“精致”。检查中文、英文、数字和长标题的实际排版。

**密度。** 同类记录优先连续列表，避免每一行都是独立阴影卡片。
主要标题形成稳定扫描列，编号、分类、评论和时间各有固定位置。
窄屏让次要信息换行或重排，不裁掉主标题、关键状态或操作；状态不只靠颜色表达。

**形状与层次。** 小控件可以用胶囊形，大面板使用小圆角；统一边框和图标线重。
明显投影优先留给产品展示或真实浮层，不为普通列表行添加投影。
不因“需要填满页面”而添加无关卡片、徽章、背景纹理或装饰性大字。

**组件与交互。** 首页突出真实产品；列表突出可扫读性；文档突出合理行宽。
复用既有组件和语义 HTML。实现任务范围内的 hover、focus、active、disabled、loading、empty、error 状态。
导航用链接；筛选用合适的表单或按钮语义；不要仅因外观像分段控件就错误使用 tab 角色。
尊重减少动态效果的偏好，不做持续吸引注意的无功能动画。

### 5. 验证、修正，再交付

交付前阅读 [验收清单](references/qa-checklist.md)，运行项目中实际存在且适用的测试与构建命令。
能运行浏览器时，以真实内容检查桌面、平板、窄屏及相关主题，并查看截图而不只生成截图。
重点检查长标题、空列表、键盘焦点、折叠内容、移动端操作区和主题切换。
发现问题后修正并复查；环境限制阻止验证时，明确列出未验证项。

使用附带 CSS 色板时，可从 skill 根目录执行：

```bash
python scripts/check_contrast.py --css assets/tokens.css
```

这个脚本只检查指定不透明颜色对的对比度，不能代替运行界面的可访问性测试。
改变了色板、透明度或组件实际背景后，应重新测试实际配色。

## 交付格式

实现任务：交代修改范围与运行入口、关键设计决策、实际完成的验证、剩余限制。
评审任务：按影响排序，给出“具体位置 → 观察到的问题 → 修改动作 → 验收方式”，不要只写审美形容词。
不为交付说明堆积长篇设计宣言，不把未执行检查标为通过。

## 维护这个 skill

修改触发条件或设计规则后，用 [评估用例](references/evaluation.md) 检查命中、误触发、视觉输出和功能回归。
把重复出现的实际失败转成具体规则；删掉没有帮助、互相冲突或只适用于一次任务的指令。
