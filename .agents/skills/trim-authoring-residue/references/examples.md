## 必须保留的近似表达

- “只接受当前和上一轮 token 密钥。”描述运行时有效期；“上一轮”不指实施会话。
- “旧 generation 的结果返回 Stale。”描述并发领取有效性，不能去掉关键条件。
- “日志契约版本 2 使用物理阶段与独立期限范围。”版本有实际字段和语义，应保留。
- “将 schema v1 迁移到 v2 的事务失败时回滚。”描述支持的数据库升级行为。
- “取消等待不代表数据库线程已经停止。”属于必要的负面保证。
- “未经完成确认就关闭数据库可能丢失待保存结果。”解释保护机制的作用，不属于评审辩护。
- “先关闭生产者，再排空接收队列。”若用来解释队列终止条件或操作步骤，应保留顺序。
- “测量使用固定输入和模拟服务时间，不代表公网吞吐。”应连同测量来源保留，不能只留下数值。
- 历史报告中的阶段名称、失败记录和未验证范围属于证据；源码路径按报告对应版本理解。

## 信息归属与误删风险

操作手册中的“第一批通过 344 项测试，第二批出现 Locked”属于具体运行记录。整理时可移入有真实日期和版本依据的报告；手册保留现行命令、成功判断及报告链接。不能把“该次未运行公网测试”改写成永久规则“禁止公网测试”。

迁移说明可以记录旧字段与新字段的对应关系，方便真实消费者升级；当前事件表应直接描述当前字段。不能因用户不要求兼容旧日志，就删除识别历史数据所必需的版本边界。

孤立注释“先增加 i，然后检查 i”通常只重复语法；“先登记等待者再释放锁，避免遗漏唤醒”解释竞态顺序。审查后者必须理解同步机制，不能仅因出现“先／再”就删除。

使用本页校准搜索时，既检查“本轮新增”等候选能否被发现，也确认 token 轮次等合法表达被保留。本 skill 自身引用这些反例是教学用途，不作为残留问题报告。
