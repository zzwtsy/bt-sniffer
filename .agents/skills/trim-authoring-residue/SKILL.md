# 文案残留与事实完整性

目标是让读者仅凭当前文件和可取得的引用理解内容，不依赖编写会话。先确定授权范围：只读审查不改写，修复任务处理已证实的问题；命中词不是问题结论，不自动扩大全仓范围。

## 审阅方法

检查引用能否取得、正文是否描述当前行为、条件和失败后果是否完整。将“阶段二”“按上次结论”等无独立意义引用改为明确规则或有效链接；将实施流水账改为当前机制。必要迁移说明、历史事实、设计理由和解释测试同步关系的注释不是残留。

核对每个保证的证据，区分当前实现、实际运行结果与推断。删文字前确认没有丢失所有权、取消、顺序、单位或异常后果；不要为了简短删除理解边界。未知动机不编造，来源许可与原始记录不伪造。

生成文件从其源处理，不跨符号链接或进入用户运行数据。历史证据按用户授权范围处理，不擅自删除或改写为当前保证。项目写作及信息归属见[文档规则](../../../docs/development/documentation.md)。

## 参考与输出

需要扩大召回时读[审查提示](references/recall-batteries.md)，需要措辞比较时读[正反例](references/examples.md)，不要求每次全部加载。正则只找候选，最终逐段结合上下文判断。

结论给文件位置、触发条件、影响和证据，区分必须修复、建议和待验证推断。修复后核对事实未丢失、链接仍有效，运行适用的 docs 检查；纯文案不宣称业务回归通过。许可证和来源元数据继续保留。
