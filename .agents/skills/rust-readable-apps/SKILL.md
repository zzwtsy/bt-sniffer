# Rust 实现与审查

## 确定行为与所有者

先读适用 AGENTS、Cargo 配置和工具链，定位入口、调用者、状态所有者及相关测试。区分功能实现、保持行为的整理和只读审查；不把删除能力或改变并发包装成代码清理。

给出可观察验收条件，核对输入校验、失败、超时和取消后果。跨模块修改先确定依赖与状态归属；本项目目录规则完整定义在[源码目录设计](../../../docs/architecture/repository-layout.md)，业务约束从该页进入专题，不在 skill 维护参数。

## 直接而可读的实现

优先具体类型、普通函数和直接控制流。函数围绕一个业务动作组织，用名称说明真实阶段；入队不叫完成，取得许可不叫建立连接。可以提前返回、使用 `?` 或 `let ... else`，不把副作用藏在复杂迭代链中。

仅在真实调用者和变化原因要求时抽象。保留防止无效数据流动的类型与资源约束，不为了短代码删除校验、事务或背压。提取函数前后核对校验顺序、事务范围、await 位置及并发推进方式。可见性从私有开始，不为测试扩大生产 API。

中文契约说明非显然的用途、参数单位、状态所有者、返回区别、失败与取消后果。模块说明给入口和协作对象；字段与枚举解释业务含义；实现注释说明原因而非逐行翻译。没有实际信息的模板不添加，复杂机制不能因函数私有而省略说明。

## 按需参考

- 流程、命名、注释与抽象示例见[示例](references/examples.md)，只读对应问题。
- 借用、分发或错误类型疑问进入 [rust-best-practices](../rust-best-practices/SKILL.md)，不默认读全部章节。
- 任务所有权、取消、背压、锁、阻塞或退出问题进入[异步专项](../rust-async-patterns/SKILL.md)。
- 事件、输出或消费者变化进入[日志专项](../bt-sniffer-logging/SKILL.md)，普通 Rust 修改不扩展日志改造。

## 验证与审查

先跑受影响行为测试，再按项目[验证指南](../../../docs/development/validation.md)选择范围，使用现有 feature 与锁文件。复读完整 diff，确认实现、注释和对应业务文档一致；通过后没有新变化不重复检查。

审查给位置、触发条件、影响和证据，区分必须修复、可选建议与待验证推断。交付列实际命令、结果及未覆盖范围，不把测试存在当成本次运行通过。文案有会话残留时按需使用[文案审查](../trim-authoring-residue/SKILL.md)。
