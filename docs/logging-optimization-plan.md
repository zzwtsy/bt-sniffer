# 日志优化实施计划

## 目标

处理文件文本解析、生产 DEBUG 不可用、投递丢弃不可观察和部分事件缺少稳定字段的问题。
保留分类聚合、样本预算、Applied 提交口径及退出资源边界。

## 实施顺序

1. 建立 bt-sniffer-logging skill 并接入 AGENTS.md，日志文档维护项目字段契约。
2. 契约升级为 3：stderr 文本、文件 JSON Lines、顶层 run_id、RUST_LOG 严格过滤。
3. 拆分日志初始化、标准 formatter 包装、队列诊断及测试；不增加监控任务。
4. 复用分钟摘要报告两端丢弃，最终业务错误后输出最终快照，再释放 guard。
5. 补齐运行事件，迁移消费者、当前文档和测试，保留历史报告与旧日志。

## 边界

工作目录 logs/bt-sniffer.YYYY-MM-DD.jsonl 按 UTC 每日轮转，最多 7 个匹配文件。
旧 .log 不混写、不删除、不计入新上限；磁盘字节配额与告警由部署层负责。
保留两个 4,096 条 lossy 队列。无格式 CLI、热更新、外部指标服务或逐任务 span。
即时故障与退出诊断明确阶段，不通过字符串全局去重改变错误历史或退出结果。

## 验收

- skill 结构校验及新增样本、异步上下文、过滤修改、文案审查四类任务走查。
- JSON 类型、转义、缺失值、span 及跨线程/第三方运行标识。
- 默认、空值、模块 DEBUG、全局级别、off、非法/非 Unicode 过滤。
- 慢 writer 独立推进、丢弃累计/增量、最终快照、初始化失败和 SIGTERM 收尾。
- 轮转数量、旧文件保留、消费者截断末行和完整坏行处理。
- skill/链接/diff 校验及 fmt、check、clippy、默认本地测试。

不启用 ignored 公网长测、不部署、不提交或推送。实际验证在交付时报告；本计划不是测试证据。
