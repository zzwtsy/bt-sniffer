三个阶段已完成本地验证：诊断与旧策略基线、Q 接纳修订、回归与固定输入比较。服务器证据及上一轮报告保持原样。完整配置、源码清单和结果见 [JSON 报告](first-attempt-buffer-2026-09-13.json)。

## 固定输入结果

两组使用并发 4、M=10000、B/R=16/16 和真实 SQLite 事务/领取代码。服务时间由逻辑时钟模拟，没有执行公网下载。两策略收到相同的已观察 hash；暂停不会改变夹具输入，采样恢复命令由独立 collector → dispatcher 集成测试验证。

| 指标 | 空闲重试：旧 → 新 | 竞争：旧 → 新 |
| --- | --- | --- |
| 初始 34 个 hash 未获首试数 | 34 → 0 | 34 → 0 |
| 初始首试年龄 P95 | 未全部获领 → 8 秒 | 未全部获领 → 160 秒 |
| 新策略最晚初始首试 | 8 秒 | 165 秒 |
| Hint/Recent/Retry/History 领取数 | 0/0/0/0 → 0/34/0/0 | 363/0/60/61 → 269/94/60/61 |
| 成功提交数 | 0 → 34 | 96 → 122 |
| 保存 hash 数 | 84 → 84 | 9328 → 9328 |
| 活跃峰值 | 50 → 66 | 9138 → 9206 |
| 数据库调用 P95 | 175 → 296 μs | 4378 → 8054 μs |

空闲组有 50 条五分钟后到期的重试，34 条新任务每条服务 1 秒，观察 60 秒。新策略全部首试≤15秒，实测最晚8秒。竞争组含 9000 历史、50 重试、64 提示和34初始近期 hash，随后每10秒一条采样、每5秒一条 announce；服务5秒，固定成败规则和退避，观察600秒。新策略 P95=160秒满足≤180秒；历史和重试各自最大领取间隔10秒。缺少首试时 P95 记为缺失，不将未获领 hash 排除后宣布达标。

两组新策略补建前后的 Q 峰值为16，最终 running=0，数据库关闭后 WAL 消失。旧策略在起始即暂停，观察期内未恢复；新策略在这两种时序中均未触发暂停。单独集成测试先实际暂停，再通过真实领取释放 Q：仍有66条近期活跃任务时，低水位持续30秒后 dispatcher 的 collector_paused 被解除；存储暂停继续优先。

新策略获得首试机会的同时，竞争夹具活跃量和数据库调用耗时也上升。数据库调用包含专用线程排队与执行，P95 为一次基线/最终运行观测，不是纯 SQL 或 CPU 测量，不据此宣称公网吞吐提升。Q 查询计划使用 fetch_due 状态索引以及 hash/hint 主键，输入受活跃容量限制；无需新增索引或表字段。每秒两类补建扫描均断言≤128行。未增加全库未接纳 hash 的周期精确计数。
