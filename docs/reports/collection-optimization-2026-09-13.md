## 阶段一：诊断

- 原 v1 connect/handshake/transfer/verify 聚合和分钟输出保留，新增标准握手、扩展协商分类诊断。错误按类型识别，实际发生阶段随 peer 计时器保留，外层任务期限用真实触发标记区分普通取消。
- 固定维度为阶段、IPv4/IPv6、Announce/Dht 来源、结果和期限。成功/失败/取消分别计数及累计耗时，不保存长期 hash/IP 标签。任务最终失败类别仍只代表本轮最终原因。
- 领取时固定 Hint/Recent/Retry/History 类别，并记录本轮到期等待、首次发现年龄和执行结果；新增 12、18 小时桶。Downloaded 表示网络成功，MetadataCount 才表示提交成功。
- 启动记录包版本和有效配置；生产所有事件携带同一 run_id。分钟摘要记录提交、领取、TCP 尝试、实际 worker、积压和暂停原因，退出输出最后区间。

握手回归覆盖标准/扩展无响应、分段、EOF/reset、协议/hash 错误、不支持扩展、成功、peer/任务期限和取消。默认期限测试让标准握手先耗时 3 秒，验证扩展协商仍在总共 5 秒时超时，不能重新计时到 8 秒。

这些本机测试证明分类机制有效，不能回答原公网日志中握手失败的细分占比。需部署后读取新 peer_diagnostic 的 interval/total 分布；不要用任务最后一次失败推算全部 peer。

## 阶段二：调度、接纳和背压

领取轮转为提示、近期、提示、历史、提示、近期、提示、重试；空类按提示、近期、重试、历史借用。所有类别必须到期，提示刷新不穿透退避；事务内完成分类、generation 递增和提示读取。提交结果后立即补位，每秒 tick 维护到期和补建。

仅 sample+fetch 的 freshness 启用近期额度 B=min(M,4C)、预留 R=min(B,M−1)，默认 16；容量 1 不预留。完整保存采样 hash，近期和历史补建各最多检查 128 条/秒。历史不能占用预留；已有超限任务自然消化。延迟批次保留原始观察时间，按当前处理时间判断接纳。announce 保留总容量接纳和已接纳任务提示刷新。

近期活跃达到 16 暂停主动采样，降至 4 并持续 30 秒恢复；历史积压不再单独暂停采样，容量/存储暂停不能被近期低水位解除。capacity、仅采样、仅采集保持原接纳策略，公平领取适用于所有采集模式。

真实 SQLite 固定输入：9,000 个历史 hash，600 秒逻辑时间，每秒 4 个新 hash，每 10 秒一个有效提示；4 个 worker，每项服务 5 秒，序号可被 3 整除时成功，其余永久失败并按指数退避重试。随机 jitter 仅在夹具内消除。基线使用同一 Release 测试程序中保留的旧 3∶1 SQL 和原接纳规则；两组提供同样已观察输入，**不模拟旧主动采样暂停，也不是公网吞吐比较**。

| 指标 | 旧策略基线 | 新策略 |
| --- | ---: | ---: |
| 提示 / 近期 / 重试 / 历史领取数 | 121 / 0 / 0 / 359 | 134 / 21 / 199 / 126 |
| 近期首试发现年龄 P95 | 无领取样本 | 20,000 ms |
| 成功提交 | 138 | 70 |
| 活跃任务峰值 | 10,000 | 9,016 |
| 保存 hash 数 | 11,400 | 11,400 |
| 领取调用 P95，含专用线程往返与事务 | 1,915 µs | 3,706 µs |

新策略使近期、历史和重试都获得服务；近期不再被历史 FIFO 挡住。此输入下各类别并非一直非空，借用导致统计比例不等于固定 4∶2∶1∶1；八次轮转及互斥分类由独立测试验证。

**公平性存在产出取舍**：夹具中的失败资源永久失败，给重试服务会减少首试机会，所以成功提交下降；不能把公平领取解释为成功吞吐必然提升。查询多检查类别，最终 P95 仍高于旧策略。执行计划确认到期索引、重试部分索引及 first_seen/hash 覆盖索引生效，不使用临时排序。

## 阶段三：并发和资源

输入固定为 1,000 个可校验的微小 metadata、双栈 DHT 和本机 TCP peer。每个 hash 先返回慢 peer（6 秒不完成标准握手，触发原 5 秒期限），再返回正常 peer（标准握手/传输各延迟 100 ms）；四分之一目标使用 IPv6。每组顺序运行 120 秒，4/8 交替，重复三轮，DHT 配额与其他配置一致。

该固定负载下，并发 8 的成功吞吐中位数提高 **30.3%**。CPU 时间中位数增加 0.06 秒，RSS 峰值中位数增加 124 KiB；这两个指标的进程范围与采样限制见下文。所有组均有 IPv4/IPv6 有效 DHT 响应和成功 metadata 阶段；慢 peer 的失败归入 StandardHandshake/Timeout/Stage，关闭取消单独计数。

成功 TCP 建连 P95 是阶段成功的桶上界，包含后来握手失败的连接；成功标准握手均值由成功阶段 sum_ms/count 计算，不能混入超时。成功标准握手 P95 在 500 ms 桶内，扩展协商 P95 在 1 ms 桶内；失败约 5 秒可能因毫秒调度误差落入 10 秒桶，不表示配置延长。

CPU/RSS 是整个测试进程，包括 Collector、SQLite、DHT 及模拟服务；RSS 每秒采样，六组共享同一进程和分配器，不能作为生产 worker 的精确增量内存。存储 stats 调用耗时包含排队/线程往返，不代表所有写事务。成功数在 Collector 收尾后读取，120 秒边界上已完成的结果仍允许提交；CPU 采样截至窗口结束。原始组数据和指纹见[机器可读记录](collection-optimization-2026-09-13.json)。
