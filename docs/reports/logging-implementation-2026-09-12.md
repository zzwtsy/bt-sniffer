# 日志实施记录

四阶段已完成：日志配置入口、有界异步 stderr、聚合 JSON v1、文档与默认验证。采集调度、DHT 配额、schema 和 metadata 字节未改变，未操作用户 state 或提交 Git。

- 阶段一：过滤、非法 Unicode、空配置、终端颜色短测通过。
- 阶段二：受控慢 writer 验证队列饱和时生产者继续推进、丢弃计数、释放输出端后实际写入量与 guard 排空。
- 阶段三：真实 JSON 事件捕获验证过滤、数值类型、空样本、溢出、区间重置、具名 DHT 类别和最终数据库快照。
- 最终：287 项默认测试通过、0 失败、5 项忽略；fmt、严格 Clippy、Release 构建、Git 差异检查通过。CLI help/version 不受非法日志环境影响；非法过滤、非法 Unicode 和未知格式被拒绝，未创建状态目录。

固定输入 Release 短比较使用 128 条、每条 12 字节的相同内容。输出端被受控门闩阻塞时，同步 writer 未能在释放前完成，异步 writer 完成并记录丢弃；解除门闩、回收生产者及 guard 后，写入条数加丢弃数等于 128。健康输出端两种 writer 均写入全部 128 条且无丢弃。具体结果及源码清单见 [JSON 报告](logging-implementation-2026-09-12.json)。

慢输出场景将测试队列缩至 2 条以确定性制造饱和；健康场景使用生产配置的 4,096 条。50 ms 是完成观察窗口，不是实测磁盘延迟或响应性能承诺。本测试证明 writer 调用边界，未测公网吞吐、生产日志流量、RSS 或日志持久落盘。

锁定 tracing-appender 0.2.5 的 guard 关闭投递和刷新交接分别最多等待 100/1,000 ms；位于会话 30 秒清理及 runtime 收尾之后。丢弃计数不检测全部底层 I/O 故障，其报告也可能被过滤或丢弃；详细行为、v1 字段迁移、回退文本命令和 systemd 示例见 [日志说明](../logging.md)。

未自动启动 30 分钟混合压力或两小时公网验收；历史报告保持原样。新二进制为 `target/release/bt-sniffer`。
