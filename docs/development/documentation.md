# 文档写作与同步维护

文档修改先读 [docs/AGENTS](../AGENTS.md) 和[文档目录设计](../architecture/documentation-layout.md)，再核对负责的源码、配置及测试。规则适用于根 README、项目 Markdown 和本地 skill 说明；外部参考资料保留来源与专有结构。

## 事实与表述

每个业务专题先给定位、主要源码入口和验证入口。正文回答实际问题，使用简体中文与准确代码名称，解释条件、所有者、单位、顺序和失败后果。删除逐行 Rust 教学、无依据的保证、会话编号和实施流水账；保留有证据的设计理由与必要版本迁移。

只有一种维护位置保存完整参数表、状态机或事件字段表，其他页面链接它。关键取舍交代当前依据、替代方案、代价及重访条件；不能把未知历史动机写成事实。审查结论给出位置、触发条件、影响与证据，区分必须修复、建议和待验证推断。

## 链接与示例

使用仓库相对 Markdown 链接和真实标题锚点，文件名与大小写准确。代码块标语言，标题不跳级，列表与表格前后留空行。不为通过格式检查批量改写上游参考资料。

操作命令应说明工作目录、依赖与授权前提、副作用、成功判据和停止方式。纯片段标明省略的上下文；不要把公网启动包装成无副作用的快速验证。精确测试名从当前测试列表核实，不能仅凭旧文档照抄；命令执行 0 tests 不构成通过。

## 变更触发的同步核对

| 变更 | 同时核对 |
| --- | --- |
| CLI 默认、冲突、目录与地址 | config、调用者、参数测试、running；启动事件配置字段 |
| 模块或状态所有权 | 模块声明、调用者、repository-layout、overview 或 lifecycle |
| 协议校验、任务状态、事务 | 对应 domains、失败与恢复测试、直接消费者 |
| 日志字段或输出 | logging / log-events、事件类型测试、Python 解析和诊断说明 |
| 检查工具或 CI | validation、workflow、真实入口反例测试 |
| 文档移动与删除 | 根入口、docs 导航、skills、脚本和源码注释引用 |

文档检查执行 docs；检查工具也改动时加 tools。自动格式和链接只能证明结构，不能证明设计合理、取消正确或事实完整。完成前人工沿任务路径检查是否能找到模块、约束、测试和联动位置。证据与覆盖局限如实交付，不在当前手册中积累执行报告。
