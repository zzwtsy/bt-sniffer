# 原始 metadata 采集

## 数据与状态

`--fetch` 将主动采样、合法宣布和历史 hash 接入同一任务表。IPv4 与 IPv6 共用 hash 主键、并发预算和 SQLite，不重复领取同一 hash。

- `infohashes`：发现记录，包含首次与最后观察时间；存在记录不表示已经获取 metadata。
- `fetch_jobs`：`pending`、`running`、`retry_wait`、`dormant`、`succeeded`。领取时递增 `generation`，结果提交必须匹配当前领取标识。
- `peer_hints`：合法宣布提供的短期地址，每个 hash 最多 8 条，有效期 30 分钟。过期地址不用于连接，清理每批最多 1,024 条。
- `metadata.info`：经过原始字节哈希与字典结构校验的 info BLOB，保持接收字节不变。它不是完整 `.torrent` 文件，也不保证种子字段语义有效。

首次升级事务创建 schema v2；失败不会留下半个迁移。历史任务每批最多检查 256 条；freshness 下与近期补建各检查至多 128 条。已经存在 metadata 的 hash 不重新下载；已领取任务在重启后恢复，旧领取结果不能覆盖新任务。

成功保存 metadata、完成任务和删除对应 peer hints 共用事务。网络请求是允许重复的操作，SQLite 完成记录是幂等的。数据库提交失败时不会出现只有 metadata 或只有成功状态的半提交。

## 调度与边界

到期任务先按 `generation > 0` 归重试（无论是否有提示），未领取任务再按有效合法 hint 归提示首试，其余按 `first_seen` 是否在最近 30 分钟内区分近期与历史首试。固定轮转为“提示、近期、重试、提示、历史、近期、重试、提示”，对应提示／近期／历史／重试份额 3∶2∶1∶2；四类持续到期时 First/Repeat 领取机会为 3∶1，不是执行时间配额。空类按提示、近期、历史、重试借用，跳过已查询类别。类内按 `due_at, hash` 排序，仅成功领取推进轮次，提示刷新不绕过退避。结果提交后立即补足 worker，每秒 tick 继续发现新到期任务。分类、提示存在性与时间随领取结果冻结；恢复和本地取消后的再次领取属于重试。schema 保持 v2，使用现有索引。

每个任务立即启动 DHT 查找，有合法新鲜 hint 时同时开始连接。首两个 hint 优先，其后先消费已到达的 DHT 结果，再尝试剩余 hint。worker 自己驱动查找与单个 peer future，不为线索创建后台任务；容量为 32 的结果通道通过非阻塞发送交付双栈去重地址。获取成功会取消未结束的查找并回收待发和在途请求；peer 失败时继续等待查找补充。每族同时最多 3 个查询、累计最多 32 个查询、候选最多 256 个，按目标 hash 的 XOR 距离选择最近候选。查找最多持续 30 秒，两族合计保留最多 32 个 peer。已获得的 peer 不因查找期限到达而丢弃。每族只读一次初始 seeds；未查询、在途、成功、失败分别记录，失败项退出有效 shortlist，备用节点按 XOR 距离补入，已尝试 ID/地址仍去重。

节点引用只作为候选；直接收到身份与来源匹配的合法响应后才更新可信路由。peer 地址遵循当前公网/本地地址策略及启用的地址族。查找结果不冒充合法宣布写入 PeerStore，本程序不会为了下载而发送 `announce_peer`。

任务全程最多 180 秒、8 个不同 peer；单 peer 使用 30 秒期限、4 MiB metadata 上限、分片和累计接收预算。TCP 连接按 IP 互斥，使用 Tokio 公平 semaphore；等待可取消，许可随尝试释放，最后一个持有者或等待者退出时回收 IP 条目。新 `get_peers` 使用全进程与每 IP 发包间隔，仍保留至少一个非采集 transaction 名额。取消 future 会撤销该查询，不等待普通网络超时。

采集调度在一次运行内使用单调时钟推进 UTC 锚点，避免系统校时改变已经安排的退避；磁盘仍保存 UTC 毫秒，重启沿用持久化期限。

发现入口存在两个不同保证：采样结果通过有界队列背压保存；合法宣布通过有界通道尽力投递。宣布通道满载或暂停时计数并丢弃，DHT ACK 不代表采集落盘。进程崩溃也可能丢失尚未提交的事件；已经提交的任务可以恢复。

## 容量与故障

`--sample --fetch --sample-backpressure freshness` 使用近期首试缓冲控制发现压力。设总容量 M、并发 C，B=min(M,4×C)，历史补建预留 R=min(B,M−1)；容量 1 不预留。默认 B/R=16/16。Q 同时满足 `first_seen` 在 `[now−30分钟,now]`、generation=0、状态为 pending/retry_wait、无未过期且符合当前 AddressPolicy 的提示。Q 包含未到期首试；重复观察不延长 first_seen。运行、有提示和已领取过的重试不占 Q，但仍占总活跃容量 M。`recent_active` 指标包含运行与重试，只用于观察。

每秒先检查硬保护，再有界补建和领取；每 5 秒用更新后的 Q 判断背压。达到 B 暂停主动采样；降至 floor(B/4) 以下或相等并持续 30 秒恢复，默认 16/4。高于低水位会重置恢复计时。历史积压和最老到期等待继续报告，不单独触发暂停。容量、磁盘和存储暂停优先，Q 下降不能解除其他暂停。

采样批次完整保存 hash，新任务统一由补建创建，避免新批次抢先占满额度。近期补建按 first_seen/hash 游标每秒最多检查 128 行，要求总活跃<M 且 Q<B；历史补建按 hash 游标最多检查 128 行，要求总活跃<M−R。额度检查与创建在同一事务，游标停在未接纳候选之前。到页尾绕回；延迟插入在当前游标之前的观察要等下一轮，不承诺全局 FIFO。超过 30 分钟的 hash 转入历史补建。重复观察按 24 小时冷却再激活 dormant，保留 generation；补建本身不复活 dormant。

领取事务递增 generation 后立即释放 Q，无需等待成功或休眠。announce 可使用总容量，满载时继续刷新已有活跃任务提示，R 不限制 announce。提示失效、地址策略变化或旧库可能使 Q 暂时超过 B；不驱逐已有任务，只停止补建，等待自然释放。失败转为重试后不占 Q，因此总活跃可能更快接近 M；由重试退避、六次远端失败后休眠及容量保护限制活跃量。

首试缓冲仅在同时启用采样与采集的 freshness 模式生效；capacity 及仅采集按总容量接纳，仅采样保存发现记录而不创建下载任务。四类公平领取适用于所有采集模式。新发现机会以有总容量、任务能持续结束为前提，不保证硬容量已满或存储故障时继续接纳。

活跃任务达到配置上限时仍暂停主动采样；宣布仍经有界入口提交，存储允许刷新已接纳任务的 hints，事务拒绝新 hash。低于 80% 后解除硬容量暂停，只有其他暂停原因也解除才恢复主动采样。已经在途的采样结果允许保存 hash，之后补建任务。成功与休眠记录保留，不自动删除已有结果。

每 5 秒检查 SQLite 与 WAL 大小；剩余预算不足 64 MiB 时停止新增采集和任务领取，取消网络任务，保留状态。软容量阈值允许检查间隔和在途写入产生超额，不替代操作系统配额。暂停后需要正常重启，不能通过自动删除结果腾空间。

磁盘写入失败会上报会话故障，停止采集，DHT 服务继续运行。普通远端失败进入退避；无路由、取消等本地条件不计失败。失败原因保存为有限类别，不保存无限增长的尝试历史。DHT 控制失效、配置错误、worker panic 或意外取消会结束会话，并保留操作或领取标识；异常收尾仍回收其他 worker，存储可写时提交成功结果，未完成任务延期且不增加远端失败次数。

关闭共用 30 秒期限：停止发现与领取、取消网络、处理已完成结果和可写事件、保存路由、关闭数据库。期限耗尽或写入失败返回非零退出码；超时报告清理阶段并保留此前已上报的错误。未确认结果不宣称已落盘，异步等待超时也不代表数据库线程已经停止。

## 验收证据

默认测试覆盖本机采样/宣布/历史 hash 到 metadata 入库、IPv4/IPv6、迭代候选验证、重复去重、查询取消、事务回滚、旧领取标识失效、休眠重新激活、容量保护、数据库故障监督和正常退出。

两个长时间测试通过完整测试名与 `--ignored` 单独执行（不要运行无筛选的全部 ignored 测试），命令见 README。30 分钟本机混合流量测试检查有界任务、DHT 响应及 Linux RSS；公网两小时测试使用默认双栈配置，记录采集统计、RSS 和每族验证响应数，正常退出后执行 SQLite integrity_check 并逐条复核 SHA-1 与完整字典。两项长测支持 Ctrl-C/SIGTERM，独立 JSON 报告区分中止和通过；未实测地址族保持未验证。公网测试不以邻居数量代替 metadata 成功，成功条数为零时判定未通过。

DHT 共享速率保护默认启用，配置与预算分配见 README。公网互操作通过也不表示完成告警和磁盘硬配额验收。生产部署能力与本版原始 metadata 采集能力分别评估。

运行统计仅保存固定大小聚合：60 秒区间与累计计数、固定桶近似 p50/p95/p99（`p50/p95/p99_upper_bound_ms` 为毫秒桶上界；溢出由对应 `exceeds_ms` 字段给出超过的上界，同时输出溢出数量；不适用字段缺省），以及当前到期数量、最老到期等待和新鲜任务数。DHT 日志包含各类发送包/字节、入站与回复、限流丢弃、待发超时和 IP 表占用。事务返回 Applied/Stale，只有 Applied 增加提交计数。

领取等待桶延伸到 5/10/30 分钟、1/2/6/24 小时，网络阶段最大有限桶为 180 秒。TCP 连接、握手及扩展协商、传输、校验分别在实际执行处记录成功/失败/取消和耗时。连接尝试失败与任务失败分别计数。查找开始、结束（含取消）、首次 peer、成功后取消分别统计；跨区间开始和结束数不能直接相除。

DHT 日志按 collector/control/sampling/verification 输出具名 class。`dht_class` 记录待发接纳及结束原因，进入发送不等于 socket 发送成功，实际发送看 `packets`。`dht_wait_reason` 按类别配额、目的 IP 配额、发送字节和 IP 表容量区分原因，每请求每原因只计一次。历史数组对应关系见[日志迁移说明](logging.md#从日志契约-1-迁移到-2)。反向验证额外记录在途重复、冷却、名额或 IP 表拒绝，以及实际成功/失败。每 IP 接纳间隔 60 秒，换端口或 Node ID 不绕过冷却；双栈共享默认 10 个待发验证名额，发送或未发送结束后释放。

`主动采样背压` 输出组合暂停原因、累计暂停毫秒及恢复次数；`AnnouncesAccepted` 包含已接纳任务的 hint 刷新，不等于新 hash 数。`admitted_tasks_database` 是数据库总任务数，包含历史记录。正常关闭在任务落库后补齐采集统计，dispatcher 回收后输出最终 DHT、数据库状态和关闭结果。

## 采集诊断与服务器复测

每分钟输出 Bencode 样本计数、First/Repeat 领取成本与 Applied 提交统计，以及包含有提示、未到期和超龄任务的未首试积压快照。分类含义、缺失值和关闭边界见 [日志契约](logging.md#bencode-样本与领取历史诊断)。诊断本身不改变策略；当前调度版本 2 和扩展握手版本 2 的行为变化见本页调度说明及日志契约。

[服务器手动复测步骤](diagnostics-validation.md) 要求从首次日志观察到有效采样后继续至少 35 分钟，正常 SIGTERM 收尾并只读核对数据库。它用于确认统计和资源边界，不设置吞吐提升门槛，也不替代现有两小时公网互操作验收。

诊断覆盖扩展握手键序检查、领取类别与 First/Repeat 联合统计、短期端点连接历史，以及首试到期等待。它们只用于解释成本和等待，不改变运行策略；字段及覆盖限制见 [日志说明](logging.md#键序领取与连接历史诊断)。

## 扩展握手兼容与收益

仅扩展握手在严格解析返回 InvalidDictionary 后尝试有界乱序规范化；所有层级重复键、截断、非法编码、尾随数据和字段错误仍拒绝。兼容最多 4096 字节、64 层且服从原配置，规范化输出再次完整严格解析。严格路径能接纳的大于兼容预算的输入不受额外限制；metadata 消息头、原始 info、SHA-1、分片与会话期限均保持原规则。

`VerifiedMetadata` 仅携带成功来源会话的兼容标记，不写入数据库。失败 peer 的兼容不能归功于后续严格 peer 的下载；帧接纳、使用兼容的会话数、下载、Applied 提交分别统计。不得把少了多少 InvalidDictionary 直接当作多获得多少 metadata。

## 实现与所有权

入口 `collection::Collector` 一次创建共享指标与 PeerClient；所有 worker 共用 Peer ID、指标和同 IP 许可表。`ingest` 保存采样批次与提示，`scheduler` 驱动补建、领取与背压，`worker` 控制候选优先级、地址筛选、去重、最多 8 个候选和失败切换。PeerClient 不另设候选循环或全局 semaphore。单次调用上限为 120 秒，整轮 180 秒、peer 30 秒、连接 5 秒、共用握手 5 秒和分片 10 秒分别限制相应执行范围。

CollectionStore 负责采集业务 SQL，DhtStore 负责身份、路由快照和采样冷却，二者复用同一 SQLite 线程。大载荷在复制前申请预算，调用者取消等待不撤销已接纳数据库命令。退出保存与正常提交使用同一 Applied 判断；远端失败重试和退出取消延期分别处理。

采集配置控制并发；worker 的 `MAX_PEER_ATTEMPTS` 固定为 8。peer 配置只控制单 peer 的协议、接收预算与期限；初始化错误和网络执行错误分别返回，普通取消只安排本地延期。

worker 共享 `WorkerResources`，DHT 查询节奏由 `LookupPacer` 管理，同 IP TCP 许可由 `TcpLimits` 管理。一个 peer 尝试持有许可至成功、失败或取消，候选切换仍由 worker 唯一编排。

任务存储按领取、状态更新、提示、快照及接纳分组；重试计算为纯函数，generation 校验和写回仍在同一事务。`SampleIngest` 保留尚未确认的分段，正常消费与退出重试共用入口。

任务耗时只由领取诊断记录：领取后一次观察时间计算 DueWait 和 DiscoveryAge，Execution 从 worker 首次 poll 到执行结束或取消，不包含数据库提交。实际收益仍以 Applied 为准。peer 阶段统一细分，完整标准／扩展握手耗时见 `peer_handshake_diagnostic`，Task 期限结果为 Timeout/Task。字段、版本与桶边界见[日志契约](logging.md#日志契约版本-3)。
